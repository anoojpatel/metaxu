The Metaxu Book

This is the language documentation: every part of Metaxu, explained with programs that run. It is written in the same discipline as the compiler itself. Each ```metaxu block in these pages is extracted by test_book_examples.py and executed through the real pipeline on every test run, and its printed output is pinned. If the language changes, the book breaks loudly.

Contents

  1. Getting started — install, run a program, what the pipeline does with it.
  2. Functions and values — fn, let, mutability, blocks as expressions, control flow.
  3. Structs and enums — product and sum types, generics, construction and field access.
  4. Pattern matching — match, binders, literals, exhaustiveness.
  5. Vectors and collections — Vec, fixed-size vector[T, N], strings, slicing.
  6. Types and inference — what you never have to write, what the checker rejects, and why.
  7. Traits — trait, implements, dispatch on the runtime type.
  8. Effects — perform, handle, resume; defaults; streams and generators built from them.
  9. Errors — try/catch, std.option, std.result.
  10. Modes and memory — locality, mutability, linearity; the borrow checker; no lifetimes anywhere.
  11. Threads and sharing — Thread and Mutex effects, inferred thread-safety, std.sync.
  12. The standard library — a tour of std/, module by module.
  13. GPU tiles — Tile, kernels, the Gpu effect, Metal.
  14. Compiling to native — clang, the differential contract, measured performance.
  15. Modules and imports — import, export, visibility, multi-file programs, name precedence.
  16. Unsafe and FFI — unsafe, extern C, the strict simulated heap, the native boundary.
  17. Inside the compiler — the pipeline stage by stage, the house rules, how to poke at it.

How the examples work

A plain metaxu fence is a complete program. The output fence after it is the program's exact stdout; the test harness runs the program and compares byte for byte.

An error example is a program the compiler must reject; its output fence holds a fragment of the diagnostic. Rejections are part of the language and get pinned like everything else.

A norun fence is display-only (used for multi-file layouts the single-source harness can't run). The harness caps how many of these the book may contain, so the escape hatch stays narrow.

Influences

The shape of this book borrows from the Rust book, the Swift guide, Ante's documentation, and Jane Street's OxCaml writing on modes. The ideas in chapter 10 owe the most to the last two.
