A systems language with algebraic effects, mode-based memory safety, and tile-level GPU kernels compiled to Metal.

You write what should happen; handlers decide where it runs: a test, a thread pool, an Apple GPU. Memory safety comes from inferred modes, with no lifetime annotations. And the compiler is readable Python that emits text, built so you can learn from it.

// why

A wall can carry a message

The name is Simone Weil’s metaxu: the wall between two prison cells separates the prisoners, and it’s also what they tap messages through. That’s the goal. The barrier between your intent and the machine should be the thing that transmits it: high-level code, low-level results, nothing lost between them.

The second goal is access. Systems languages tend to gatekeep, and compilers tend to be black boxes. Metaxu’s compiler is plain Python that emits text at every step, written to be read, so that learning how a language works is part of using one.

// design

Three decisions shape everything

Effects are the machine model. Most languages weld their concurrency in: threads are threads, exceptions are exceptions, async needs its own keywords. Here they’re all one thing, an effect: an operation a function performs without saying how it’s done. A handler upstream decides that. It’s why the same kernel function runs on a sequential CPU loop under a test and on a Metal GPU in production, unchanged.

Modes replace lifetimes. Memory safety without a garbage collector usually means lifetime annotations. Metaxu instead tracks a few small properties of each value: local to its region or free to escape, mutable or shared, consumable once or many times. The checker infers and propagates them; you annotate to demand a guarantee, not to satisfy the compiler. Thread-safety follows the same rule. Nothing is declared Send: capture a shared value in a spawned closure and unsynchronized writes to it become errors, caught statically where provable and at run time otherwise, with one wording either way.

The interpreter is the spec. A strict reference interpreter defines what every program means, and each backend must reproduce it byte for byte: stdout, exit codes, error messages, float formatting. A backend that gets something subtly wrong fails a differential test before it reaches a user.

Streams are effects; consumers are handlers

One mechanism carries exceptions, generators, threads, and GPU launches. Here it carries a stream: each element flows from iota through two handlers into sum by suspending and resuming, one element at a time. No iterator protocol, no intermediate collections. It prints 39999799994.

streams.mxchapter 8 of the book, where this example runs as a test
from std.stream import iota, map, filter, sum;

fn main() -> int {
    let total = sum(filter(map(iota(200000), fn(x: int) -> x * 2),
                           fn(x: int) -> x > 5));
    print(total);
    0
}

Five small kernels, each with a hand-written C twin. A Metaxu build asserts output equality with its twin before any timing runs. // the asterisks. These are microbenchmarks, and microbenchmarks reward whoever wrote them. The kernels are tiny and fit in cache. We keep the table because it pins regressions and keeps performance in view while the language grows, not as a scoreboard against C. Read every ratio as "in the same neighborhood," nothing finer.
